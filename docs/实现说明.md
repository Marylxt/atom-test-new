# Atoms Demo · 实现说明

> 一句话概括：用户输入一句需求，三位 AI Agent 接力产出**可直接运行的单页应用**，
> 全程 SSE 实时可见、iframe 即时预览、Supabase 版本持久化、一键发布成公开链接。
>
> 本文回答三个问题：**为什么这么设计**、**做到哪了**、**继续投入该做什么**。
> 技术细节看 [README](../README.md)，本文只讲判断。

---

## 一、实现思路与关键取舍

### 1. 为什么是"多智能体接力"，而不是一个 Agent 干到底

单个 Agent 拿一句需求直接写代码，能出结果，但**过程不可控、失败不可归因**。
拆成「🧑‍💼 产品经理 → 🏗️ 架构师 → 👨‍💻 工程师」之后：

- 每一步的输入输出都是**可预期的结构化文本**，能单独测、单独换模型、单独限流；
- 出错时能立刻定位是哪一环（是需求没拆清？还是方案不可落地？）；
- 演示时"三位接力"本身就是可讲的故事。

代价是**延迟叠加**：实测 pm 2.5s + 架构师 14.2s + 工程师 30.7s = 全程 55s。
但我仍然选串行 —— 这三步是严格依赖关系，并行化在业务上不成立。

> 预留了 `AGENT_MODE=tool / agent` 两种编排模式（走 LangChain `@tool` 层、
> 或交给 `create_agent` 自主编排），默认用 `chain`：因为只有 chain 能逐 token 回吐进度，
> 前端才有"打字机"体验。

### 2. 三个"anti-AI"的工程防御（都是踩坑后加的）

AI 生成的内容有个特点：**看起来对，跑起来错**。所以不能只靠 Prompt，得靠机制。

| 防御 | 解决什么问题 | 代价 |
| --- | --- | --- |
| `extract_html()` 稳健抽取 | 模型爱把代码包在 ``` 里、还夹带解释文字 | 取最长 HTML 代码块 + 截 `<!DOCTYPE>`→`</html>`，兜住解析 |
| **产物静态质量门**（`html_check.py`） | 一个括号打错 → 浏览器丢弃整个 `<script>` → 页面看着正常、交互全死 | 多跑一次 `node --check`；未装 node 时自动跳过 |
| 不合格自动自修一轮 | 静态检查报错后，把**行号 + 出错源码**回吐给「工程师（自修）」Agent 再改 | 多一次 LLM 调用（实测 19.8s） |

静态门是**踩了真坑才加的**：生成的番茄钟多写了一个右括号，人肉 Review 没看出来，
`node --check` 一行命令就定位到行号。详见 README 第九节。

### 3. 产物形态：单文件 HTML，而不是 React 工程

| 选项 | 优点 | 代价 |
| --- | --- | --- |
| **单文件 HTML（选它）** | 生成即交付、iframe 直接渲染、零构建、易分享 | 产物规模受输出 token 上限约束，复杂应用做不了 |
| React/Vue 工程 | 能力上限高 | 要装依赖、要构建、要部署，Demo 闭环从 1 分钟变成 10 分钟 |

判断依据：这个 Demo 的核心价值是**"需求 → 可运行应用"的闭环速度**。
单文件 HTML 能让闭环压到 1 分钟内，这是它不可替代的优势。

### 4. 实时预览：iframe + sandbox，而不是 `dangerouslySetInnerHTML`

生成代码可能包含 `document.write`、访问 `parent.*` 等越权操作。
`iframe srcdoc + sandbox` 是浏览器提供的**硬隔离边界**，产物再野也只能在自己盒子里折腾。

必须开 `allow-same-origin`（产物要用 localStorage 做持久化），这也意味着**产物与宿主同源**——
所以这是 Demo 级方案，生产环境应该把产物放到独立域名或 Docker 沙箱里再渲染。
**这个取舍我明确写进 README 了，不当成"已经安全了"。**

### 5. 进度推送：SSE，且必须手写解析

- **为什么不用 WebSocket**：进度是单向、短时、秒级的推送，双向能力用不上，还要自己管心跳重连。
  SSE 走标准 HTTP，穿透代理、浏览器自动重连。
- **为什么不用原生 `EventSource`**：它只支持 GET，而生成接口必须 POST（要带需求文本 + 鉴权头）。
  所以用 `fetch` + `ReadableStream` 手写帧解析。
- **token 合帧**：增量 token 攒够 32 字符才推一帧。一个 20KB 产物原本会产生上千条事件，
  合帧后只有几十条 —— 用一点实时性换掉大量无意义的网络往返。

### 6. 数据模型：版本只追加不可变，"回滚"是生成新版本

```
projects ──1:N──> versions ──1:N──> publications
                      │                  └─ public_id 短链，指向具体版本
                      └─ parent_version_id 串成链
```

- **回滚不是把指针指回旧版本**，而是以历史版本为蓝本**生成一个新版本**（`change_type=rollback`）。
  好处：历史只追加、可审计、且"回滚"本身还能被再回滚。
- **发布指向具体版本**：老链接永远指向当时那版代码，不会因为后续修改而变。
- **产物与过程分离**：`versions` 存代码，`generation_events` 存过程日志，方便复盘"哪一环慢/挂"。

### 7. 存储双轨：Supabase 为主，本地 SQLite 兜底

Demo 的核心之一是 Supabase 持久化，但"必须先注册 Supabase 才能跑"会让评审者连界面都看不到。
所以数据层做了个门面（`repository.py`），底下挂两个**同签名实现**，`STORAGE_BACKEND=auto`
时自动判断：配了 Supabase 用云端，没配就落到本地 SQLite。

代价是**要维护两套实现**。为此加了 `scripts/check_backends.py` 做**接口契约测试**——
自动比对两边的方法是否齐全、是否都是协程、门面调用是否都有实现。
（这个脚本是为了修一个真实 bug 才写的：`supabase_store` 漏了 `ping()`，切到 Supabase 后启动直接崩。）

### 8. 认证：后端用 service_role 绕过 RLS

后端所有数据库操作走 `service_role`，简化了实现（不用把用户 JWT 一路透传到 SQL 层）。
同时 RLS 策略**照写不误**，作为"前端万一要直连 Supabase"的安全网。

登录态用 Supabase Auth 签发 JWT，后端双通道校验（HS256 用共享密钥 / ES256、RS256 走 JWKS），
兼容 Supabase 新旧签名体系。

> 本地联调留了 `AUTH_DISABLED=true` 的免登录模式 —— 这在演示场景下非常好用，
> 但**不能当成"认证已经跑通"**（见第二节）。

### 9. 运维细节：能自动化的绝不让人肉做

| 脚本 | 解决什么 |
| --- | --- |
| `scripts/provision_supabase.py` | 一个 Personal Access Token 搞定：建表 → 取回三样 Key → 写回配置 → 真读库校验 |
| `scripts/check_backends.py` | 两个存储后端的接口契约测试 |
| `scripts/init_db.py` | 有数据库连接串时的手工建表路径 |
| `scripts/smoke_llm.py` | 模型通路自检 + 可选的完整流水线冒烟 |

`provision_supabase.py` 顺带解决了一个隐蔽问题：**走 Dashboard 的 SQL Editor 时 Supabase 会自动
套用默认权限，走 Management API 就不会** —— 不显式 `GRANT` 就会报 `42501 permission denied`。
所以 `schema.sql` 里补上了显式授权，让两种执行方式结果一致。

### 10. 跨区域链路的隐性成本（最容易被忽略的一条）

数据库在境外时，瓶颈往往不在 SQL 而在**建连接**。实测（本地 → Supabase 悉尼）：

| 场景 | 延迟 |
| --- | --- |
| 每次新建连接（DNS + TLS） | **2 ~ 17 秒** |
| 复用同一连接池 | **0.5 秒** |

httpx 默认 `keepalive_expiry=5s`，请求间隔一超就断连 → 接口延迟在 0.5s / 14s 之间随机跳。
三招解决：注入自定义 `httpx.Client` 延长保活、后台每 20s 打一个轻量查询焐住连接、
读操作重试 3 次。**写操作绝不重试** —— 实测踩过：请求报超时，但数据其实已经落库了，
盲目重试会写重复数据。

配套还有一条**优雅降级**：生成成功但落库失败时，产物照常下发（带 `warning` 字段），
前端顶部显示黄色提示。**宁可数据没存上，也不能让用户等了 60 秒却什么都看不到。**

## 三、如果继续投入，我会怎么扩展

排序依据是 **「验证价值 ÷ 成本」**，不是"哪个听起来酷"。
对一个要拿去做演示/评审的项目，**可信度 > 功能量**。

### P0 —— 不做的话项目站不住

**1. 自动化测试套件 + CI（最高优先级）**

理由：现在所有验证都是我手工跑的一次性脚本，**改一行代码就可能悄悄回归**。
而这是个"AI 生成代码"的项目，最该展示的恰恰是**工程化的质量保障能力**。

具体做法（都是现成素材，成本低）：
- 把 `smoke_llm.py` / `check_backends.py` 升级成 pytest 用例；
- **SSE 协议测试**：注入假 LLM，断言事件序列、断线、模型报错都能落到 `error` 事件而非静默挂死；
- **静态门单测**：坏产物 / 好产物 / 截断产物的判定（已有代码，补断言即可）；
- **双后端参数化测试**：同一套 CRUD 断言跑两遍（SQLite / Supabase）；
- GitHub Actions：push 即跑，`node --check` + pytest + `tsc --noEmit` + `next build`。

**2. 把 QA Agent 变成默认质量门，形成闭环**

理由：现在流水线是「生成 → 静态检查 → 交付」，缺了**语义层的验收**。
静态检查只能挡住"跑不起来"，挡不住"逻辑错"（比如我们踩的另一个坑：改了输入框但显示不同步）。

具体做法：`ENABLE_QA_STAGE=true` 设为默认，让 🧪 测试工程师 Agent 输出**结构化缺陷清单**
（级别 / 复现步骤 / 期望 vs 实际 / 修复建议），在工作台里以面板展示，并支持"一键把缺陷单交给工程师修复"
—— 也就是把我这次手工做的流程（发现缺陷 → 提交 modify → 验证）固化成一键操作。

**3. 产物沙箱加固**

理由：现在产物与宿主同源（`allow-same-origin`），是我明确标注的 Demo 级妥协。
做法：产物托管到独立域名（或独立子域），去掉 `allow-same-origin`；
要执行后端代码时再上 Docker 沙箱。做完这条，"安全"才不是一句空话。

### P1 —— 显著提升可信度

**4. 真实登录链路跑通并验收**
把 `AUTH_DISABLED` 关掉，走完整注册 → 登录 → JWT → RLS，并**验收多用户隔离**：
A 用户看不到 B 的项目（这是 RLS 策略第一次真正被行使）。

**5. 版本 diff 视图**
能回滚但看不到差异，对"多轮迭代"的场景是缺失的。有了 diff，"改了什么、有没有改坏"一眼可见 ——
这几乎是测试视角的刚需。

**6. 成本与延迟优化**
- DeepSeek 的**缓存命中输入**与未命中价差很大，把 System Prompt 固定在前缀可以显著命中缓存；
- `modify` 从"重发全文"改成"只发差异 + 让模型输出 patch"；
- 产品经理与架构师两轮可考虑换更小模型（铺垫工作只需要格式化文本，实测可省约 30% 时间）。

### P2 —— 锦上添花

7. **生成产物缩略图**：生成完成后截图存 Storage，列表卡片有预览。
8. **可观测性看板**：把各阶段耗时、token 数、失败率落库，做一个简单的统计页——
   这既是产品功能，也是"这个系统能被度量"的证据。
9. **模板市场**：预置常见应用骨架（待办 / 记账 / 番茄钟），
   让 LLM 只填业务逻辑不重复造轮子 → 更快、更稳、更省 token。
10. **真正部署上线**：Vercel + Railway 跑通，接真实域名，做一轮**线上验收**
    （含 CORS、SSE 在 CDN 后的表现、健康检查）。

### 如果只做一件事

**把 P0-1 和 P0-2 一起做掉**：一套能跑的自动化测试 + 一个默认开启的验收闭环。

因为这两个东西合起来，才真正回答了那句最有价值的话：

> **AI 能快速产出"看起来能跑"的页面，而"看起来正常"和"真的能用"之间，隔着一次验收。**

这个项目的意义不在于"能生成代码"（这已经不稀奇了），
而在于它把**验证**做成了流水线里的一道自动关卡 —— 这才是测试工程在 AI 时代的落点。
